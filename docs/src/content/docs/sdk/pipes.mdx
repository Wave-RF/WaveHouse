Named pipes are server-defined, parameterized queries (see the [Named Pipes guide](/pipes)). Both SDKs run a pipe for the roles it allows, and read the pipes' definitions under the admin gate. The examples assume a client called `wh` (see [Creating a Client](/sdk#creating-a-client)) and, in Go, a `ctx`.

## Running a pipe

<Tabs syncKey="lang">
  <TabItem label="TypeScript">

```ts
// PipeRef is PromiseLike, so these are equivalent:
const { data } = await wh.pipe('top_pages', { start_date: '2026-01-01', limit: 50 }).fetch();
const { data: same } = await wh.pipe('top_pages', { start_date: '2026-01-01', limit: 50 });
```

`wh.pipe(name, params?)` returns a `PipeRef`, sent as `POST /v1/pipes/{name}` with the parameters as a JSON body. Its `.fetch(opts?)` takes `PipeRequestOptions`: `signal`, `attemptTimeoutMs`, `headers`, `fetchOptions` and `fetch` ([Per-call options](/sdk/queries#per-call-options)), but no `limit`. A pipe's row cap belongs in its SQL as a `{{limit}}` parameter, passed as `wh.pipe(name, { limit })` as above.

`limit` is typed `never` rather than left out, so passing one is a compile error, even through a variable. That cuts both ways: a value *declared* as `RequestOptions` is rejected whether or not it carries a limit, since the type permits one. To share one options object across calls, type it as `PipeRequestOptions`, which the query builder's `.fetch()` accepts too.

  </TabItem>
  <TabItem label="Go">

```go
var rows []struct {
    Page  string `json:"page"`
    Views int64  `json:"views"`
}
err := wh.Pipe("top_pages").Param("limit", 10).Param("pages", []string{"/home", "/about"}).Scan(ctx, &rows)
if err != nil {
    log.Fatal(err)
}
```

`wh.Pipe(name)` returns a `*wavehouse.PipeCall`, sent as `POST /v1/pipes/{name}` with the parameters as a JSON object. `Param` and `Params` set parameters and return a copy, like the query builder. `Scan` and `Fetch` read rows with the rules of a [query](/sdk/queries#reading-rows); `Exec` discards them, for a pipe that writes. `Header(key, value)` sets a header on this call.

  </TabItem>
</Tabs>

Parameters are JSON-encoded: an array (a Go slice) becomes an `IN`-style list on the server, and an object is refused with `400`. The pipe's `allowed_roles` decide who may run it; with none, only the admin role may. A [pipe that writes](/pipes#pipes-that-write) answers with no rows. The pipe's parameter list is in its [definition](#reading-pipe-definitions).

### Retries

A pipe may write, so both SDKs resend a pipe call only when it can't have run, or when the server says it is safe:

- **A transport error** (a dropped connection, a timeout) is retried only when the connection was certainly never made. Once the request may have reached the server, it is returned as the error, marked not retryable.
- **An answer** is retried only when the server's body says `retryable: true`, or it is a `429`, or a `503` with `Retry-After` (as for a server with no ClickHouse connection open, refused before anything ran). A bare `5xx`, which a proxy in front can send after the write ran, is returned as the error.

A pipe that writes answers every ClickHouse failure `retryable: false`, so a failed write is never resent: check whether it landed before you send it again. A proxy that answers `503` with a `Retry-After` after the write ran is the one case where a write could still run twice. See [Retries and timeouts](/sdk/reference#retries-and-timeouts) for the waits.

## Reading pipe definitions

The admin routes list the adopted pipes. They need the admin gate: the admin role (`policy.admin_role`) or the [operator key](/api#authentication). Pipes are defined in the server's settings directory, in `pipes.json`, and the files are the only way to define or change one, so there is no set or delete: edit the file and let the server pick it up, or [reload the settings](/sdk/admin#settings).

<Tabs syncKey="lang">
  <TabItem label="TypeScript">

```ts
const { data: pipes } = await wh.pipes.list();
const { data: pipe } = await wh.pipes.get('top_pages');
// pipe: { name, sql, parameters, description, allowed_roles }
```

  </TabItem>
  <TabItem label="Go">

```go
pipes, err := wh.Pipes(ctx)
if err != nil {
    log.Fatal(err)
}
for _, p := range pipes {
    fmt.Println(p.Name, p.AllowedRoles)
}

p, err := wh.PipeDefinition(ctx, "top_pages") // an unknown pipe is ErrNotFound
if err != nil {
    log.Fatal(err)
}
for _, param := range p.Parameters {
    fmt.Println(param.Name, param.Type, param.Required)
}
```
